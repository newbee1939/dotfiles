# End Session（セッション終了・Linear 更新）

セッションの終わりに **Linear の対象チケットを最新化**し、次回すぐ再開できる状態にする。
Linear の操作は Linear MCP のツール（`mcp__linear*`）を使う。

## 手順
1. **対象チケットを特定する**。ブランチ名・直近の会話から推定し、曖昧なら自分の未完了チケットを一覧して確認する。
2. **このセッションでやったことを集める**: `git log --oneline --since=midnight`、`gh pr view`（あれば）、Slack の自分の投稿（`mcp__slack*`）、会話の要点。
3. **コメントを 1 件追記する**（日本語・5 行以内）:
   - やったこと
   - 現状（PR の状態、詰まっている点）
   - **次回やること = 再開ポイント**
4. **チケット本文のタスクリストを更新する**。実際に完了したものだけ `- [ ]` → `- [x]`。
5. 状況が変わっていれば**ステータスを更新**する（In Progress / In Review など）。
6. 更新したチケットの **URL を提示**する。
7. **このセッションで扱った技術的な内容について、Claude から問題を出題する**（学びの定着チェック）。
   - このセッションで触れた技術的トピックのうち、OS・ネットワークなど低レイヤーに関わるものを 1 つ選ぶ
     （該当が薄ければ、最も「仕組み」を問える題材を選ぶ）。
   - **Claude が Q を出題する**。用語の暗記ではなく「なぜそうなるか」「どういう条件で起きるか」を問う設問にする。
     （例: 今回 `exit 137` が出た → 「なぜ 137 という数字になるか説明してください」）
   - **ユーザーの回答を待つ**。
   - 正誤を判定する。
     - 合っていれば、足りない部分があれば補足する。
     - 間違っていれば、**一段下の仕組みまで解説する**（プロセス管理・シグナル・ソケット・TCP/IP スタックなど該当する層まで踏み込む）。
   - このセッションに出題できるような技術的な深掘りポイントが無ければ、無理に出さず「今回は出題なし」と明示する。
8. **このセッションで使った git worktree が不要になっていれば消す**。
   - `git worktree list` でこのセッションのブランチに紐づく worktree を確認する。
   - PR がマージ/クローズ済みか、作業が完全に終わっているかを確認する。
   - 未完了・判断がつかない場合は消さない。**削除前に必ずユーザーに確認を取る**（`git worktree remove` は元に戻せない操作のため）。
   - 確認が取れたら `git worktree remove <path>` で削除し、不要なら対応するローカルブランチも `git branch -d` で消す。

## 原則
- 憶測で完了にしない。**git ログ・PR・Slack の自分の投稿**で確認できたものだけチェックする。
- コメントは「翌朝の自分が読んで 5 秒で再開できる」粒度にする。長い経緯は書かない。
- 1 セッション 1 コメント。細かく分けない。
- 出題は学びの確認が目的。**答えを教える前に必ずユーザーの回答を待つ**。
