# Extract Learnings（学びの抽出）

今日のすべてのセッションから学びを拾い、**次に使える原則**まで抽象化する。

## 1. 今日のセッションを集める
```bash
# 1 ファイル = 1 セッション（24 時間以内に更新されたもの）
find ~/.claude/projects -name '*.jsonl' -mtime -1

# 中身のテキストだけ読む
jq -r '.message.content? | if type=="array" then map(.text // empty) | join("\n") else . // empty end' <file>
```
長いセッションは全部読まず、詰まった箇所・やり直した箇所を拾う。

## 2. 学びを拾う
- うまくいかず**やり直したこと**と、その原因
- 知らなかった仕様・挙動・ツール
- 判断に迷った点と、最終的にどう決めたか
- 進め方やコミュニケーションで効いたこと / 効かなかったこと

## 3. 抽象化する
各学びを「具体」と「そこから引き出した原則」の 2 段で書く。原則は**次に同じ状況が来たときそのまま使える**言い方にする。

- ✗ 「jq の使い方を学んだ」（具体で止まっている）
- ✗ 「事前確認が大事」（一般論すぎて行動に落ちない）
- ○ 具体「jq のパースに失敗して 2 回やり直した」→ 原則「出力形式が不安定なコマンドは、パイプで加工する前に一度中身を見る」

## 4. 出力
学び 1 個 = `##` セクション 1 個。タイトルは**何の話か一言で**分かるものにする。
```markdown
# 今日の学び（YYYY-MM-DD）

## <学びのタイトル>

### 具体的な学び
<今日実際に何が起きて、何が分かったか。ログ・エラー・コマンドなど事実で書く>

### 具体的な学びを抽象化した学び
<次に同じ状況が来たときそのまま使える言い方。1〜2 行>

## 一段下が説明できなかったこと
- <今日触った技術で、その下の層（OS / ファイル / ネットワーク）を説明できなかったもの 1〜2 個>

## 次に試すこと
- <1〜2 個>
```
「一段下が説明できなかったこと」は翌日の `deep-dive` のネタになる。

## 原則
- **3〜5 個に絞る**。全部書くと何も残らない。
- 教科書的な一般論は書かない。今日の自分の経験から出たものだけ。
