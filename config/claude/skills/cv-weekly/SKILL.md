# CV Weekly（今週の仕事を職務経歴書に追記）

今週の仕事を**漏れなく**拾い、職務経歴書（cv.md）にそのまま貼れる形で**表示する**。ファイルは編集しない（貼り付けは本人が行う）。
週次でやる理由は 1 つ。**改善前の数値・件数・判断の理由は、時間が経つと取り戻せない**から。文章を磨くのは `/cv-brushup` の役割で、ここでは事実を取りこぼさないことを優先する。

期間は今週月曜 00:00〜現在。引数で指定されたらそれに従う。

## 1. 集める

全ソースを見る。検索結果は 1 ページ目で止めず、最後まで取る。

| ソース | 取るもの | ここでしか拾えないもの |
|---|---|---|
| Linear（`mcp__linear*`） | 自分アサインで期間中に更新・完了したチケット、自分のコメント | 仕事の背景・課題 |
| GitHub | `gh search prs --involves=@me --updated=">=<開始日>" --limit 200 --json repository,title,state,url` | 実装、**他人の PR へのレビュー** |
| Slack（`mcp__slack*`） | 期間中の自分の投稿すべて（スレッド返信を含む） | チケットにならない仕事: 障害対応、他チームの相談対応、提案、調査結果の共有 |
| Google Calendar（`mcp__*calendar*`） | 期間中の予定 | 登壇・勉強会、ベンダーや他部門との打ち合わせ、採用面接、障害の振り返り |
| TIL（[newbee1939/til](https://github.com/newbee1939/til)） | 今週分。一覧は `gh api repos/newbee1939/til/contents/YYYY/MM --jq '.[].name'`、本文は `gh api repos/newbee1939/til/contents/YYYY/MM/DD.md -H "Accept: application/vnd.github.raw"` | 公開できるエビデンスリンク、キャッチアップした技術 |

接続できないソースは黙って飛ばさない。報告に「未取得」と書く。

## 2. 束ねる

同じ仕事はソースをまたいで 1 項目にまとめる（チケット + PR + Slack の相談 + 会議 = 1 つの仕事）。各項目を次の形にする。

- **何を**: やったこと
- **なぜ**: 背景・課題。規模の分かる数字
- **判断**: 選んだ方法と理由、除外した選択肢、捨てたもの。**自分の判断か、会社・チームの決定か**
- **困難**: 一番詰まったこと、最初に立てて外れた仮説、どう乗り越えたか
- **成果**: 数字（前 → 後、件数、時間）と、誰の何が変わったか
- **技術スタック**
- **根拠**: チケット ID・PR・Slack の投稿

ソースで確認できない欄は空のままにする。

除外するのは定例会議・雑談・単なる返信だけ。ルーチン運用（権限付与、問い合わせ対応など）は捨てずに **件数として 1 行**にまとめる。件数は経歴書の規模感になる。

## 3. 聞く

空欄のうち、**来週には取れなくなるもの**（改善前の数値、件数、所要時間、その判断をした理由）を優先して、AskUserQuestion で最大 5 問だけ聞く。うち 1 問は必ず、今週いちばん大きい仕事について「一番困難だったことは何か。どう乗り越えたか」に充てる。答えが出なかった欄は埋めずに「要確認」として残す。

## 4. 提示する

```
## 取得件数
Linear N 件 / PR N 件（うちレビュー N 件）/ Slack N 投稿 / 予定 N 件 / TIL N 件 → N 項目に集約
未取得: <ソース — 理由>
除外: <件数と理由>

## 追記案
<cv.md にそのまま貼れる Markdown。テーマごとに 1 ブロック>

## 要確認
- <項目>: <足りない事実>
```

追記案は cv.md の形式に合わせる。

```markdown
##### <テーマ>（YYYY/MM - YYYY/MM）

- 役割: <自分の役割>
- 技術スタック: <A、B、C>
- 成果・実績
  - <成果。数字を入れる>
    - <判断の理由・仕様や制約・除外した選択肢>
    - <困難だった点と、どう乗り越えたか>
```

## 絶対に守ること

- **捏造しない**。ソースかユーザーの回答で確認できた事実だけ書く。数字・因果・役割を推測で補わない
- **社外秘を追記案に入れない**。Slack / Linear の URL、チケット ID、非公開の取引先名・金額は「取得件数」「要確認」の根拠にだけ使う
